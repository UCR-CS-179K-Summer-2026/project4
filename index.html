Warnings your compiler
won't give you.

A static analysis tool that reads a single C++ source file once, then hands the parsed result to a set of independent detectors — each one hunting a different code smell, from dead variables to copy-pasted blocks, and printing what it finds straight to the terminal.

// 01  pipeline

Architecture

One parse, many detectors. The source file is read exactly once and turned into a shared ParsedSource; every detector below just reads from it.

// 02  data model

Class & Struct Structure

Structs carry data between stages; classes carry behavior. Every detector is a subclass of the same abstract Detector, so SmellyCodeDetector can run all of them the same way.

struct

DeclaredVariable

  • name — the variable's identifier.
  • line — line number, relative to the start of its function's body, where it was declared

struct

FunctionInfo

  • functionStart — the function's signature text, e.g. int calculateCost(int itemPrice, int tax) {.
  • functionBody — the full text of the function's body.
  • line — the line number where the function body begins.
  • variables — a vector of DeclaredVariable, populated by Parser.

struct

ParsedSource

  • source — the raw, unmodified source code (including comments), read once from the input file.
  • tree — a TSTree*, the full tree-sitter parse tree for that source; this replaced the old functions vector entirely — detectors now walk this tree directly instead of reading pre-sliced function data.

class

Parser

  • parse() — takes the opened input file, reads it once into source, hands it to tree-sitter to build the tree, and returns a ParsedSource{source, tree}. Called once in main.cpp; the resulting ParsedSource is reused by every detector instead of each one re-parsing.

abstract base class

Detector

  • analyzeSource(const ParsedSource&) — pure virtual; every subclass implements this to scan the tree and return its warning count, printing warnings as it finds them.
  • visitNode(TSNode, const ParsedSource&, int&) — also part of the interface; each subclass's recursive tree-walk, dispatching to its own checks by node type.
  • Virtual destructor, since detectors are used polymorphically

class

RedundantCodeChecker extends Detector

Checks implemented

  • Unused/dead variables — declared but never referenced again in their function's body
  • Redundant boolean comparisons — x == true, x != false, etc.
  • Redundant if/else returning boolean literals — if (cond) return true; else return false;
  • Chained if-statements that should be if/else if/else — consecutive sibling ifs that each unconditionally return, with no else

class

NameAnalyzer

  • Extracts a variable's identifier name from the raw source using its byte length
  • Searches for the line number where the variable is found
  • Searches for the identifier node containing the variable declaration
  • Determines whether a given name is poor, using two different regex definitions
  • Given the name and input, outputs an error message

class

FunctionAnalyzer

  • Checks whether a function's name is poor, using NameAnalyzer's methods
  • Checks whether any of a function's parameters use a poor name, also via NameAnalyzer

class

PoorNameChecker extends Detector

  • Traverses the tree-sitter syntax tree searching for declaration or function_definition nodes
  • Once found, checks the validity of variable names using FunctionAnalyzer and NameAnalyzer

class

SmellyCodeDetector

  • Owns one Parser and one instance of every detector (RedundantCodeChecker, PoorNameChecker, ...)
  • Constructor takes the opened input file and immediately parses it, storing the result in parsedSource
  • runDetectors() — calls analyzeSource(parsedSource) on every detector and sums the returned warning counts

// 03  implementation

Modules

One file per concern. Each module below owns a single smell, or the parsing that feeds all of them.

Parser.cpp

  • parse() — reads the input file once, builds the tree-sitter TSTree, and returns ParsedSource{source, tree}
  • splitIntoFunctionBodies(), stripComments(), findDeclarations(), buildTypePattern() — legacy regex-based helpers from before the tree-sitter switch; no longer called by parse(), kept as dead code

redundantCodeChecker.cpp

  • visitNode() — single recursive walk over every TSNode, dispatching by node type (function_definition, binary_expression, if_statement, compound_statement)
  • analyzeSource() — gets the tree's root node, kicks off visitNode(), returns the total warning count
  • nodeText() — extracts a node's exact source text via its byte offsets
  • checkUnusedVariables() — flags variables declared but never referenced again
  • extractIdentifierFromDeclarator() / collectDeclarations() — resolve declared variable names from a declaration node, including pointers and comma-separated declarations
  • countIdentifierOccurrences() — counts how many times a name is referenced within a subtree
  • checkBooleanComparison() — flags x == true/x != false-style comparisons and suggests the simplification
  • checkRedundantIfElseReturn() / unwrapToReturnStatement() — flags if/else branches that both return opposite boolean literals
  • checkChainedReturnIfs() / alwaysReturns() — flags consecutive if-statements, each returning unconditionally with no else, that should be an if/else if/else chain

poorNaming.cpp

  • analyzeSource() — visits the tree's root node, returns the number of warnings found
  • visitNode() — checks whether the current node is a declaration or function_definition, then recurses into children
  • checkVariableDeclaration() — finds the declarator, extracts the identifier's name and type via NameAnalyzer, flags poor names
  • checkFunctionDefinition() — same process for a function's name and its parameters, via FunctionAnalyzer

repeatedCode.cpp

  • stripBlockComment() / stripLineComment() — remove block and line comments
  • normalizeWhiteSpace() — strips whitespace to avoid false negatives
  • isStructuralOnly() — filters out purely structural elements like {
  • findIDNode() / extractFunctionName() — locate a function's identifier via tree-sitter
  • extractCodeLines() — returns the cleaned lines of code
  • findRepeatedBlock() — uses variable window sizes and a hashmap of starting lines to detect repeated blocks
  • reportRepeatedBlock() — emits the warning for any repeated block found
  • visitNode() — walks the tree to find function_definition nodes, so detection runs per-function rather than globally
  • analyzeSource() — scans the processed lines with sliding windows, mapped into hashmaps, to detect repeats

commentChecker.cpp

  • analyzeSource() — inherited from Detector; uses visitNode() to find comments
  • visitNode() — scans the tree for functions and their preceding comments
  • scanForComments() — recursively checks inside functions found by visitNode() for comments

// 04  dependencies

APIs & Their Usage

tree-sitter

Builds the TSTree for the source file in Parser::parse(). Every detector walks this tree directly via TSNode traversal instead of pre-sliced text.

fstream

Reads the input from a C++ source file via std::ifstream.

sstream

stringstream reads the whole file into ParsedSource::source in one pass via rdbuf().

vector

Used within individual detectors — e.g. RedundantCodeChecker's internal list of collected declarations during a function's traversal — rather than as part of the shared ParsedSource.

string

Stores the raw source, node text extracted via nodeText(), and variable/function names pulled from the tree.

// 05  performance

Algorithms & Optimizations

Single-read files

Parser::parse() reads the entire input into one string in a single pass via rdbuf() — the file is read exactly once for the whole program.

Single parse, shared tree

The TSTree is built once in Parser::parse() and reused by every detector afterward, instead of each detector re-parsing the source.

Exact line numbers from the AST

Warnings use ts_node_start_point() directly against the original source, rather than manually tracked line offsets — eliminates a class of off-by-one bugs the old regex approach needed extra bookkeeping to avoid.

Hashmaps

Used in place of pairwise comparison to detect repetitions in repeatedCode.cpp.

Parallelism

runDetectors() currently runs each detector's analyzeSource() sequentially — a candidate for future parallel work.
