Warnings your compiler
won't give you.

A static analysis tool that reads one or more C++ source files, parses each file once, then hands each parsed result to a set of independent detectors — each one hunting a different code smell, from dead variables and deeply nested conditionals to copy-pasted blocks, unreachable and unused functions, bloated parameter lists, data clumps, redundant inheritance, and unfreed memory — and printing what it finds straight to the terminal, with safe fixes applied on request.

Tutorial

Install it, run it, and see what each detector actually catches.

1. Install & Build

  1. 01

    Prerequisites

    • CMake (3.10+) — cmake.org/download, or winget install Kitware.CMake on Windows. Confirm with cmake --version.
    • A C++17 compiler — on Windows, Visual Studio 2022 (Community is free) with the "Desktop development with C++" workload, which provides MSVC and the generator CMake targets.
    • Git — needed to pull in the tree-sitter runtime and grammar, which are vendored as submodules under tree-sitter/ and tree-sitter-cpp/.
  2. 02

    Clone and Set Up the Repo

    • git clone "repo-url"
    • cd project4
    • git submodule update --init --recursive

    The submodule step is required — without it, tree-sitter/ and tree-sitter-cpp/ will be empty and the CMake configure step will fail with a "not an existing directory" error.

  3. 03

    Build

    • mkdir build
    • cd build
    • cmake .. -DBUILD_SHARED_LIBS=OFF
    • cmake --build .

    This builds the tree-sitter runtime, the C++ grammar, and project4 itself. On Windows with the Visual Studio generator, the executable lands in a Debug subfolder.

  4. 04

    Run

    • cd Debug
    • ./project4.exe

    The program prompts for one or more whitespace-separated file names to analyze:

    • Enter the name(s) of the file(s) to read: first.cpp second.cpp

    Paths are resolved relative to the directory you launch the executable from. Since the build places the .exe in build/Debug, either give a relative path back up to your source files (e.g. ../../myFile.cpp), or run from the project root instead:

    • cd project4
    • ./build/Debug/project4.exe

    Warnings print directly to the terminal, one per detected smell, with the offending line number in the original source file. You'll then be prompted whether to apply automatic fixes:

    • Some detected smells in "filename.cpp" have automatic fixes available. Apply them? (y/n): y
    • Fixed file written to: filename.cpp.fixed.cpp

    The fix prompt appears independently for each successfully opened file. Choosing "y" writes a new file by appending .fixed.cpp to the original path, leaving the original untouched. Choosing "n" skips that file.

    After all files finish, the program prints the total smell count and total number of processed files. Missing or unreadable paths are reported and skipped; the run continues with the remaining files.

Unused / Dead Variable — auto-fixable

A variable is declared but never referenced again in its own scope. RedundantCodeChecker handles shadowing correctly, so a same-named variable that's actually used in a different scope isn't a false positive.

Input
int total = 0;
int unused = 42;
total += 10;
return total;
Output
Warning: [Redundant dead/unused code].
'unused' is declared but never used.
(line 2)

Redundant Boolean Comparison — auto-fixable

Comparisons like x == true or x != false that can be simplified to the variable itself.

Input
if (isReady == true) {
    start();
}
Output
Warning: [Redundant boolean comparison].
"isReady == true" can be simplified
to "isReady". (line 1)

Redundant If/Else Boolean Return — auto-fixable

An if/else that only returns opposite boolean literals, collapsible to a single return of the condition.

Input
if (score >= passingGrade) {
    return true;
} else {
    return false;
}
Output
Warning: [Redundant if/else return].
Can be simplified to:
"return score >= passingGrade;"
(line 1)

Chained If-Returns — warning only

Consecutive sibling if statements that each unconditionally return, with no else — structurally an if/else if/else chain. No auto-fix, since restructuring is a real rewrite, not a safe text splice.

Input
if (grade == 'A') return 4;
if (grade == 'B') return 3;
if (grade == 'C') return 2;
Output
Warning: [Redundant Chained-If].
3 separate if-statements each return
unconditionally; consider an
if/else if/else chain instead.
(line 1)

Unreachable Code — auto-fixable*

Any statement following an unconditional exit (return/break/continue/goto, or an if/else where both branches always exit) within the same block. *Auto-fix is suppressed if the enclosing function contains a goto or label.

Input
int compute(int x) {
    return x * 2;
    log("done"); // never runs
}
Output
Warning: [unreachable-code].
Code after this point is
unreachable. (line 3)

Unused Function — warning only

A defined function that's unreachable from main() via the call graph. Skipped entirely if the file has no main; no auto-fix, since reachability analysis is conservative and warnings must not delete possibly-live code.

Input
void legacyCalc() { /* ... */ }

int main() {
    doWork();
    return 0;
}
Output
Warning: [unused-function].
Function "legacyCalc" is defined
but never reachable from main().
(line 1)

Poor Naming — warning only

Names under 3 characters (barring i/j/k/id), booleans that don't start with is/has/can/should/was/will, generic verb-based function names, and placeholders like temp or val.

Input
int a = getDiscountedPrice(p, q);
Output
Warning: [Poor Naming].
Poor identifier name detected: 'a'.
Consider a more descriptive name.
(line 1)

Missing Comments — warning only

A function with no preceding, interior, or same-line trailing comment.

Input
int square(int n) {
    return n * n;
}
Output
Warning: [Comments].
Function has no comments.
(line 1)

Repeated Code — warning only

A run of statements structurally identical to another run elsewhere in the same function, found via AST hashing rather than exact text matching (so formatting differences don't matter).

Input
result = a + b;
log(result);
...
result = a + b;
log(result);
Output
Warning: [repeated-code].
Repeated code detected in function:
calculateCost.
In line(s) 3 to 4
In line(s) 8 to 9

Deeply Nested If — warning only

An if statement nested past a fixed depth threshold (MAX_DEPTH).

Input
if (a) {
  if (b) {
    if (c) {
      if (d) { doThing(); }
    }
  }
}
Output
Warning: [deep-if].
Deeply nested if statement.
(line 4)

Long Parameter List — warning only

A function whose parameter count exceeds a defined threshold, suggesting related arguments be grouped into a struct.

Input
void processOrder(int id, string name,
  string addr, string city, string state,
  string zip, double total);
Output
Warning: [long-param-list].
Function "processOrder" has 7
parameters; consider grouping
related arguments. (line 1)

Data Clump — warning only

A group of variables or arguments that recurs together often enough to suggest it belongs in its own type.

Input
drawRect(x, y, width, height);
...
resizeRect(x, y, width, height);
...
moveRect(x, y, width, height);
Output
Warning: [data-clump].
{x, y, width, height} recurs
together at lines 1, 3, 5.
Consider a Rect struct.

Redundant Inheritance — warning only

A class that inherits from a base class but never overrides a base function, calls a base function, or invokes a base constructor.

Input
class Widget : public Base {
    void draw() { /* unrelated */ }
};
Output
Warning: [redundant-inheritance].
"Widget" inherits from "Base" but
never uses it. (line 1)

Unfreed Memory — warning only

A path through the function that reaches a return without freeing a tracked allocation — checked independently down every branch of every if.

Input
int* buf = new int[100];
if (earlyExit) {
    return -1; // buf never freed
}
delete[] buf;
return 0;
Output
Warning: [memory-leak].
"buf" allocated on line 1 is not
freed on this return path.
(line 3)

Architecture

One parse, many detectors. The source file is read exactly once and turned into a shared ParsedSource; every detector below just reads from it and hands back its own list of Warnings, which SmellyCodeDetector merges, sorts, and prints.

// 03  major modules

Major Modules

Documentation of every major class, struct, and file — written so a new contributor can find the right module, understand what it owns, and modify it without needing to ask.

Code Structure — one file per concern

Parser.cpp

  • Reads the input file once and builds the shared tree-sitter TSTree, returning it as a ParsedSource.

SmellyCodeDetector.cpp

  • Parses the input file once at construction and owns one instance of every detector; runDetectors() merges, sorts, and prints all of their warnings, and retains them for later fix application.
  • The registered detector set is PoorNameChecker, RedundantCodeChecker, DeadCodeChecker, RepeatedCodeChecker, CommentChecker, DeepIfDetector, DataClumpDetector, MemoryChecker, LongParamList, and InheritanceChecker.

commentChecker.cpp

  • Flags functions with no preceding, interior, or trailing comment.

poorNameChecker.cpp

  • Finds variable, function, and parameter declarations in the tree and hands their names off to NameAnalyzer.

NameAnalyzer.cpp

  • Shared naming heuristics — length checks and regex patterns — used by both PoorNameChecker and FunctionAnalyzer.

FunctionAnalyzer.cpp

  • Applies NameAnalyzer's checks specifically to function names and parameter lists.

redundantCodeChecker.cpp

  • Unused variables, redundant boolean comparisons, redundant if/else boolean returns, and chained-if patterns — four checks in one traversal. The first three also generate a safe Edit for auto-fixing; chained-if is warning-only.

deadCodeChecker.cpp

  • Unreachable code after an unconditional exit (auto-fixable, unless the function contains a goto/label), and unused/dead functions unreachable from main via a call graph (warning-only).

deadCodeChecker/pointsToAnalyzer.cpp

  • Supports DeadCodeChecker's virtual-dispatch reachability analysis by tracking which concrete class types can flow through pointer variables and function parameters.
  • Collects declaration seeds, assignments, conditional-expression branches, call-argument propagation, and returned pointer values, then solves the resulting flow edges to a fixpoint.
  • Resolves a virtual call such as a->makeSound() to concrete overrides that may be reached. When no type is known, it conservatively keeps every known override reachable to avoid falsely flagging live code.

deadCodeChecker/pointsToAnalyzer.cpp

  • collectFromFunction(...) — gathers identifier references and builds points-to seeds and flow edges for one function body.
  • handleDeclaration(...) / handleAssignment(...) — records concrete declared types and pointer-to-pointer assignments.
  • handleConditionalExpression(...) — adds an edge for each identifier arm of a conditional expression.
  • handleCallArguments(...) / handleReturn(...) — propagates identifier arguments into registered parameters and values into a function return variable.
  • solve() — computes the transitive closure of the flow graph; resolveVirtualCall(...) converts inferred types into reachable qualified overrides.

FixApplier.cpp

  • Declares applyFixes() in Detector.h; collects every warning's Edit, applies them back-to-front by byte offset, and skips any that overlap one already applied.

repeatedCodeChecker.cpp

  • Finds duplicated runs of statements inside a function body using structural AST hashing and a sliding window.

DeepIfDetector.cpp

  • Flags if statements nested past a fixed depth.

longParamList.cpp

  • Flags functions whose parameter count exceeds a defined threshold.

DataClumpDetector.cpp

  • Flags variables or arguments that repeatedly appear together, suggesting they belong in their own type.
  • Builds recurring variable/argument groups and identifies frequent pairs and triples, then reports their source line numbers.
  • Calls the Google Gemini API to recommend a struct/class name for a detected data clump.

DataClumpNameGen.cpp

  • WriteCallBack() — used as a function for curl and determines how to manage the data returned from the request.
  • getKey() — fetches the API key stored in a file.
  • generateName() — verifies that the API key exists, prepares the request to the internet server, receives the response from the Google Gemini server, parses the JSON response, and returns the recommended name.
  • Requires GOOGLE_GEMINI_API_KEY in a .env file; network/API failures are reported and can leave name generation unavailable.

inheritanceChecker.cpp

  • Flags classes that inherit from a base class without ever using that inheritance — including uses of the base class from outside the subclass itself, and object-slicing usage — and offers a refactored version of the flagged code alongside the original and a changelog.

memoryChecker.cpp

  • Flags paths where allocated memory isn't freed before a function returns — recognizing delete/free() as well as custom deallocation functions collected from elsewhere in the source.

Class & Struct Reference

Structs carry data between stages; classes carry behavior. Every detector is a subclass of the same abstract Detector, so SmellyCodeDetector can run all of them the same way and collect their results into one shared list. Some warnings also carry an Edit — a safe, byte-precise fix that FixApplier can splice into the source on request.

struct

ParsedSource

  • source — the raw, unmodified source code (including comments), read once from the input file.
  • tree — a TSTree*, the full tree-sitter parse tree for that source. This replaced the old pre-sliced function/variable data entirely — every detector walks this tree directly instead.

struct

Edit

  • startByte / endByte — the byte range in the original source to replace.
  • replacement — the text to splice in; an empty string deletes the range.
  • Only produced by a check when the fix is provably safe from the AST alone — no cross-function or whole-program reasoning required.

struct

Warning

  • line — the source line the warning applies to.
  • category — a short label identifying which check raised it, e.g. "Poor Naming", "deep-if", "repeated-code".
  • message — the human-readable warning text.
  • fix — a std::optional<Edit>; empty when the check has no safe auto-fix, populated when it does.

class

Parser

  • parse() — the only public method. Reads the opened input file into source in one pass via a stringstream's rdbuf(), spins up a TSParser configured for the tree_sitter_cpp() grammar, and parses that raw source directly into a TSTree.
  • Called exactly once, in main.cpp; the resulting ParsedSource is reused by every detector instead of each one re-parsing the file independently.
  • Fails safely — if the tree fails to build, it logs an error to stderr, cleans up the parser, and returns ParsedSource{source, nullptr} rather than crashing. Every detector already checks for a null tree before walking it.

abstract base class

Detector

  • analyzeSource(const ParsedSource&) — pure virtual; every subclass implements this to walk the tree and return a std::vector<Warning> of everything it found.
  • visitNode(TSNode, const ParsedSource&, std::vector<Warning>&) — also part of the interface; each subclass's recursive tree-walk, dispatching to its own checks by node type and appending to the shared warnings vector. Detectors no longer print anything themselves — output is centralized in SmellyCodeDetector.
  • Virtual destructor, since detectors are used polymorphically

class

CommentChecker extends Detector

  • Walks the tree for function_definition nodes and checks the immediately preceding sibling for a comment node
  • Falls back to recursively scanning the function's body for any interior or inline comment
  • Also checks for a trailing comment on the same source line as the function's closing brace
  • Flags any function matching none of the above as having no comments

class

PoorNameChecker extends Detector

  • Traverses the tree searching for declaration or function_definition nodes
  • For declarations, resolves the identifier out of identifier, init_declarator, or array_declarator children before checking it
  • For functions, delegates the function name and each parameter name to FunctionAnalyzer
  • Checks every resolved name's validity via NameAnalyzer

class

NameAnalyzer

  • Extracts a variable's identifier name from the raw source using its byte offsets
  • Finds the line number a given node starts on
  • Depth-first searches a subtree for its first identifier node
  • Determines whether a name is poor using a length heuristic (with exceptions for common loop counters) plus regex checks for boolean-prefix naming, generic function verbs, and generic placeholder names like temp or data
  • Given a name and line, appends a formatted "Poor Naming" warning

class

FunctionAnalyzer

  • Checks whether a function's name is poor, using NameAnalyzer's methods
  • Iterates a function's parameter list and checks each parameter's name via NameAnalyzer

class

RedundantCodeChecker extends Detector

Checks implemented

  • Unused/dead variables — declared but never referenced again within their own scope, correctly handling shadowing. Auto-fixable: deletes the enclosing declaration statement, but only when it has a single declarator.
  • Redundant boolean comparisons — x == true, x != false, etc. Auto-fixable: replaces the comparison with the simplified expression.
  • Redundant if/else returning boolean literals — if (cond) return true; else return false; Auto-fixable: replaces the whole if/else with a single return.
  • Chained if-statements that should be if/else if/else — consecutive sibling ifs that each unconditionally return, with no else. No auto-fix — restructuring into an if/else chain is a real rewrite, not a safe text splice.

class

DeadCodeChecker extends Detector

Checks implemented

  • Unreachable code — walks each block's statements in order; once one is found to unconditionally exit (via return/break/continue/goto, or an if/else where both branches always exit), every sibling statement after it in that block is flagged. Auto-fixable: deletes the unreachable range — except auto-fix is suppressed for any function containing a goto or a label, since the reachability model doesn't account for jump targets and could otherwise delete a line another goto depends on.
  • Unused/dead functions — builds a call graph of every function, resolving known function-pointer targets and virtual calls through PointsToAnalyzer, then runs an iterative DFS from main; anything defined but unreachable (and not main itself) is flagged. No auto-fix — reachability remains conservative when a target cannot be resolved.
  • Skips the unused-function check entirely if the file has no main, since reachability can't be determined

class

PointsToAnalyzer

  • Parse the program → track pointer relationships → resolve indirect calls → build the call graph → traverse from main → report unreachable functions.
  • registerParams() records ordered parameter identities for interprocedural argument propagation.
  • collectFromFunction() performs two passes over a function body: it identifies referenced variables, then collects type seeds and flow edges from declarations, assignments, calls, and returns.
  • solve() repeatedly propagates points-to types and known callable targets across FlowEdges until no set changes.
  • pointsTo() queries inferred concrete types; resolveVirtualCall() maps those types through ClassHierarchy to qualified method names.
  • The current pass is flow-insensitive, assumes single inheritance in hierarchy resolution, and leaves nested blocks such as if/else bodies out of scope.

class

RepeatedCodeChecker extends Detector

  • Scans each function's compound_statement blocks for runs of consecutive statements repeated elsewhere in the same block
  • Structurally hashes each statement subtree so identical statements collide to the same key, regardless of exact source formatting
  • Slides a window across the block's statements, largest size first, grouping candidates by hash in an unordered_map
  • Confirms every hash match with a full structural comparison before reporting, to rule out collisions

class

DeepIfDetector extends Detector

  • Tracks nesting depth as it recurses, incrementing on entering an if_statement and decrementing on the way back out
  • Flags any if_statement whose depth exceeds MAX_DEPTH as a "deep-if" warning

class

LongParamList extends Detector

  • Traverses the tree for function_definition nodes
  • Counts each function's declared parameters and flags it once the count exceeds a defined threshold
  • Resolves the function's full name via the same identifier/declarator walk used elsewhere, for the warning message

class

DataClumpDetector extends Detector

  • Searches the tree for function_definition and compound_statement nodes
  • Inside a block, groups variables that are declared together and arguments that are passed together into the same call, using each group as a key into a map
  • The map's value, ClumpInfo, tracks how many times that exact group of names occurred and at which line numbers
  • Also checks a function's own parameter list for the same recurring groupings
  • Any group that recurs often enough is reported as a data clump, with every occurrence's line number listed

class

InheritanceChecker extends Detector

  • Traverses the tree for class_specifier nodes
  • For each class that actually inherits from a base class, scans its body for evidence the inheritance is being used: overridden functions, calls to the base class's functions, or a constructor call into the base class
  • Also checks usage outside the subclass's own body — whether any instance of the subclass accesses a member the base class defines, anywhere else in the source file — and checks for object slicing, where a subclass instance is assigned to or passed as the base type
  • If none of the in-class, external-usage, or slicing signals are present, the inheritance is flagged as redundant
  • On a redundant-inheritance finding, offers a refactored version of the code, printed alongside the original with a changelog of what changed

class

MemoryChecker extends Detector

  • Before traversing, scans the whole source for functions that themselves deallocate one of their parameters — e.g. a custom wrapper around delete/free() — and records them in deallocatingFunctions, so a call to one of those later counts as freeing the memory too
  • Tracks every memory allocation it sees, keyed by variable name and location, in trackedAllocations
  • Walks the function body and, at every if statement, branches into each possible path so both sides of a conditional are checked independently
  • Flags any path that reaches a return without the corresponding allocation having been freed first — either directly (delete/free()) or via a recognized custom deallocating function

free function

FixApplier applyFixes()

  • Declared in Detector.h, defined in FixApplier.cpp; signature is std::string applyFixes(const std::string& source, const std::vector<Warning>& warnings)
  • Collects every warning's Edit, sorts them descending by startByte, then splices each into a copy of the source — descending order means an earlier splice never invalidates a later edit's byte offsets
  • Skips any edit that overlaps one already applied, so two checks flagging the same region (e.g. a boolean simplification nested inside an if/else that's also being collapsed) can't corrupt the file — the skipped edit's warning is still reported, just not auto-applied in that pass

class

SmellyCodeDetector

  • Owns one Parser and one instance of every registered detector — PoorNameChecker, RedundantCodeChecker, DeadCodeChecker, RepeatedCodeChecker, CommentChecker, DeepIfDetector, and LongParamList — held as member objects and registered into a std::vector<Detector*> in the constructor
  • Constructor takes the opened input file and immediately parses it, storing the result in parsedSource
  • runDetectors() — calls analyzeSource(parsedSource) on every detector, merges all returned warnings into one list, sorts by line (tie-broken by category), prints each one, stores the merged list in the allWarnings member, and returns the total warning count
  • getWarnings() / getParsedSource() — const accessors exposing the retained allWarnings and parsedSource, so main.cpp can prompt for and apply fixes after runDetectors() returns

Internal API

The actual functions each module exposes, grouped by file.

Parser

  • ParsedSource parse(std::ifstream& inputFile) — reads the file once into source via rdbuf(), builds the tree-sitter TSTree using the tree_sitter_cpp() grammar, and returns ParsedSource{source, tree} (or {source, nullptr} on parse failure, logging to stderr rather than crashing)

SmellyCodeDetector

  • SmellyCodeDetector(const std::ifstream& inputFile) — parses the file immediately and registers one instance of every detector
  • int runDetectors() — runs analyzeSource() on every detector, merges the results, sorts by line then category, prints "Warning: [category]. message(line N)" for each, stores the merged list in the allWarnings member, and returns the total count
  • const std::vector<Warning>& getWarnings() const — exposes allWarnings after runDetectors() has run
  • const ParsedSource& getParsedSource() const — exposes the stored parsedSource, so callers have the original source text to pass into applyFixes()

commentChecker.cpp

  • std::vector<Warning> analyzeSource(const ParsedSource&) — initializes tree-sitter, walks the tree, and returns every "no comments" warning found
  • void visitNode(TSNode, const ParsedSource&, std::vector<Warning>&) — recurses the tree, checking each function_definition for a preceding, interior, or trailing comment
  • bool scanForComments(TSNode) — recursively searches inside a function for any comment node

poorNameChecker.cpp

  • std::vector<Warning> analyzeSource(const ParsedSource&) — visits the tree's root node and returns all naming warnings found
  • void visitNode(...) — dispatches declaration nodes to checkVariableDeclaration() and function_definition nodes to checkFunctionDefinition()
  • void checkVariableDeclaration(...) — resolves the identifier from an identifier, init_declarator, or array_declarator child, then checks it against NameAnalyzer::isPoorName()
  • void checkFunctionDefinition(...) — delegates the function's name and parameters to FunctionAnalyzer

NameAnalyzer.cpp

  • std::string extractIdentifierName(const ParsedSource&, TSNode) — pulls a node's exact text via its byte offsets
  • int getLineNumber(const ParsedSource&, TSNode) — counts newlines before the node's start byte
  • TSNode findIdentifierNode(TSNode) — depth-first search for the first identifier descendant
  • bool isPoorName(const std::string& name, const std::string& type) — flags names under 3 characters (barring i, j, k, id), booleans that don't start with is/has/can/should/was/will, function names built from generic verbs like process or handle, and generic placeholder names like temp or val
  • void outputErrorMessage(const std::string& name, const int& line, std::vector<Warning>&) — appends a formatted "Poor Naming" warning

FunctionAnalyzer.cpp

  • void checkFunctionName(TSNode functionDeclarator, ...) — extracts the function's identifier and checks it via NameAnalyzer::isPoorName(name, "function")
  • void checkParameterNames(TSNode functionDeclarator, ...) — iterates the parameter list, checking each parameter_declaration's identifier and type

redundantCodeChecker.cpp

  • void visitNode(...) — single recursive walk, dispatching by node type (function_definition, binary_expression, if_statement, compound_statement)
  • std::vector<Warning> analyzeSource(const ParsedSource&) — gets the tree's root node, kicks off visitNode(), returns all warnings found
  • std::string nodeText(TSNode, const std::string&) — extracts a node's exact source text via its byte offsets
  • void checkUnusedVariables(...) — flags variables declared but never referenced again, scoped per-declaration to correctly handle shadowing; when the enclosing declaration has exactly one declarator, attaches an Edit deleting the whole statement (plus its trailing newline)
  • extractIdentifierFromDeclarator() / collectDeclarations() — resolve declared variable names from a declaration node, including pointers and comma-separated declarations; also used to count sibling declarators when deciding whether a fix is safe
  • findEnclosingScope() — walks up from a declarator to the nearest enclosing compound_statement, so usage counting starts from the declaration's own scope
  • blockRedeclares() — checks whether a block directly redeclares a given name, used to detect shadowing
  • countIdentifierOccurrences() — counts references to a name within a subtree, skipping into any nested block that redeclares the name
  • checkBooleanComparison() — flags x == true / x != false-style comparisons, suggests the simplification, and attaches an Edit replacing the comparison expression with it
  • checkRedundantIfElseReturn() / unwrapToReturnStatement() — flags if/else branches that both return opposite boolean literals, and attaches an Edit replacing the whole if_statement with a single return
  • checkChainedReturnIfs() / alwaysReturns() / getLastStatement() — flags consecutive if-statements, each returning unconditionally with no else; no Edit is attached, since collapsing them into an if/else chain is a structural rewrite rather than a text splice; getLastStatement() skips brace tokens and comments to find a block's real final statement, which alwaysReturns() checks is itself a return

deadCodeChecker.cpp

  • std::vector<Warning> analyzeSource(const ParsedSource&) — runs visitNode() for unreachable-code (Check 5), then checkUnusedFunctions() once for unused functions (Check 6), and returns everything found

Builds the TSTree for the source file in Parser::parse(), using the tree_sitter_cpp() grammar. Every detector walks this tree directly via TSNode traversal instead of pre-sliced text.

Groups candidate statement windows by structural hash in RepeatedCodeChecker, and represents DeadCodeChecker's call graph (function name → set of names it calls) for the unused-function check.

set

Holds the DFS-visited/reachable set of function names in DeadCodeChecker::checkUnusedFunctions(), so a function reachable through more than one call path is only processed once.

Points-to flow graph

PointsToAnalyzer stores VarId-to-TypeSet facts and FlowEdges, then propagates types to a fixpoint so virtual calls can resolve to concrete class overrides.

vector

Carries each detector's std::vector<Warning> results back to SmellyCodeDetector, plus internal working lists like collected declarations, statements, or the DFS stack.

string

Stores the raw source, node text extracted via byte offsets, and variable/function names pulled from the tree.

Curl

Communicates with servers on the internet and is primarily used for the Google Gemini API request made by DataClumpNameGen.

Parses the Google Gemini API response into a JSON object so DataClumpNameGen can extract the recommended name.

Algorithms

Pseudocode for the core algorithms behind parsing and detection.

Parse — build the shared AST once

function parse(inputFile):
    source ← read_entire_file(inputFile)      // single pass, rdbuf()
    parser ← new TSParser()
    set_language(parser, tree_sitter_cpp())
    tree ← ts_parser_parse_string(parser, source)
    if tree is null:
        log_error("failed to parse")
        return ParsedSource(source, null)
    return ParsedSource(source, tree)

SmellyCodeDetector — orchestrate all checks

function runDetectors(parsedSource, detectors[]):
    allWarnings ← []
    for each detector in detectors:
        warnings ← detector.analyzeSource(parsedSource)
        allWarnings.append(warnings)

    sort allWarnings by (line asc, category asc)
    for each warning in allWarnings:
        print "Warning: [warning.category]. warning.message (line warning.line)"

    return allWarnings, count(allWarnings)

RedundantCodeChecker — unused variable check (with shadowing)

function checkUnusedVariables(node, parsedSource, warnings[]):
    for each declaration in node.declarations:
        for each declarator in declaration.declarators:
            name ← extractIdentifier(declarator)
            scope ← findEnclosingScope(declarator)     // nearest compound_statement
            uses  ← countIdentifierOccurrences(name, scope,
                        skipNestedIf: blockRedeclares(nestedBlock, name))
            if uses == 0:
                fix ← null
                if declaration.declarators.count == 1:
                    fix ← Edit(declaration.startByte, declaration.endByte, "")
                warnings.append(Warning(line(declarator),
                                         "Redundant dead/unused code",
                                         "'name' is declared but never used.",
                                         fix))

DeadCodeChecker — unused function via resolved call-graph reachability

function checkUnusedFunctions(tree, warnings[]):
      functions, hierarchy ← collect_functions_and_class_methods(tree)
      if no function named "main" in functions:
        return                                      // can't determine reachability

      pointsTo ← new PointsToAnalyzer(hierarchy)
      for each fn in functions:
        pointsTo.registerParams(fn.name, fn.parameter_names)
        pointsTo.registerFunction(fn.name)
        pointsTo.collectFromFunction(fn.name, fn.body)
      pointsTo.solve()                                // solve aliases and callbacks

      callGraph ← {}
      for each fn in functions:
        callGraph[fn.name] ← {}
        for each call in fn.body:
          if call uses a known function pointer:
            callGraph[fn.name].add(pointsTo.callableTargets(call.variable))
          else if call is a pointer-member call:
            callGraph[fn.name].add(
              pointsTo.resolveVirtualCall(call.object, call.method))
          else:
            callGraph[fn.name].add(call.direct_function_name)

      reachable ← {}; stack ← ["main"]
      while stack is not empty:
        current ← stack.pop()
        if current in reachable: continue
        reachable.add(current)
        stack.push(each callee in callGraph[current])

      for each fn in functions:
        if fn.name not in reachable and fn.name != "main":
          warnings.append(Warning(line(fn), "unused-function",
            "Function 'fn.name' is defined but never reachable from main()."))
          // warning only: deleting code based on an uncertain edge is unsafe

PointsToAnalyzer — resolve object aliases and function pointers

function collectFromFunction(functionName, body):
      referenced ← every identifier used in body, excluding plain declaration names

      for each top-level statement in body:
        if declaration of pointer variable:
          if initializer is a concrete object type:
            pointsTo[variable].add(declared_type)
          if initializer is an identifier or conditional expression:
            add_flow_edges(initializer, variable)
            if initializer names a known function:
              callableTargets[variable].add(initializer)
        if assignment target = source:
          add object and callable flow edges from source to target
        if call callee(arg1, arg2, ...):
          add edges from each argument to the registered parameter
        if return value:
          add an edge from the returned variable to function.__return__

    function solve():
      repeat until no set changes:
        for each object flow edge source → target:
          pointsTo[target] ← pointsTo[target] ∪ pointsTo[source]
        for each callable flow edge source → target:
          callableTargets[target] ← callableTargets[target]
                        ∪ callableTargets[source]

    function resolveVirtualCall(pointer, method):
      if pointsTo[pointer] is empty:
        return every known override of method   // conservative fallback
      return the nearest override of method for each concrete type in pointsTo[pointer]

RepeatedCodeChecker — structural-hash sliding window

function findRepeatedBlocks(statements[], warnings[]):
    covered ← set()
    for windowSize from len(statements) down to 2:
        groups ← {}                             // hash -> list of window start indices
        for i from 0 to len(statements) - windowSize:
            if any index in [i, i+windowSize) already in covered: continue
            h ← combinedHash(statements[i .. i+windowSize])
            groups[h].append(i)

        for hash, positions in groups:
            if len(positions) < 2: continue
            confirmed ← [p for p in positions
                         if subtreesEqual(window(positions[0]), window(p))]
            if len(confirmed) >= 2:
                mark covered for every index in every confirmed window
                warnings.append(reportRepeatedBlock(confirmed, windowSize))

DataClumpDetector — pairs for triples

function findDataClumps(variables):
    create a bitset for each variable
    // 1 = variable is in the set, 0 = variable is not in the set

    frequentPairs ← []
    for each pair of variables:
        intersect their bitsets
        if the pair appears more than two times:
            frequentPairs.append(pair)

    frequentTriples ← {}
    for each pair in frequentPairs:
        for each variable:
            if the three variables appear together more than two times:
                frequentTriples.add(pair + variable)

    store line numbers for each triple
    format the warning
    call Google Gemini API to recommend a struct/class name

The bitsets and frequent-pair search each cost O(n^2). Intersecting the bits for a potential pair costs O(1). Searching for triples costs O(F * N), where F is the number of frequent pairs and N is the number of variables. The detector supports data clumps of three variables; checking every possible repeated subset would cost at least O(2^n).

FixApplier — apply all safe edits without corrupting offsets

function applyFixes(source, warnings[]):
    edits ← [w.fix for w in warnings if w.fix is not null]
    sort edits descending by startByte           // back-to-front splice

    result ← copy(source)
    lastAppliedStart ← infinity
    for edit in edits:
        if edit.endByte > lastAppliedStart:
            continue                              // overlaps a prior edit — skip
        result ← result[0:edit.startByte] + edit.replacement + result[edit.endByte:]
        lastAppliedStart ← edit.startByte

    return result

// 05  performance

Optimizations & Refactoring

Optimizations considered and applied over the course of the project.

Single-read files

Parser::parse() reads the entire input into one string in a single pass via rdbuf() — the file is read exactly once for the whole program.

Single parse, shared tree

The TSTree is built once in Parser::parse() and reused by every detector afterward, instead of each detector re-parsing the source.

Exact line numbers from the AST

Warnings use ts_node_start_point() directly against the original source, rather than manually tracked line offsets.

Structural hashing

RepeatedCodeChecker hashes each statement subtree once, then groups window-sized runs by a combined hash in an unordered_map — avoiding pairwise comparison across a function body. Only same-hash candidates pay for the full structural equality check that guards against collisions.

Largest-window-first sliding search

findRepeatedBlocks() tries the largest possible repeated window before smaller ones and marks matched statements as covered, so a big repeated block isn't also reported as several smaller overlapping ones.

Depth-tracked traversal

DeepIfDetector increments/decrements a counter as recursion enters and exits if_statement nodes, flagging only once nesting passes MAX_DEPTH, instead of a separate pass to compute nesting depth per node.

Call-graph reachability

DeadCodeChecker builds a directed call graph from the file's function definitions and runs an iterative, stack-based DFS from main, tracking visited functions in a set — any defined function the DFS never reaches is unused/dead code.

Centralized sort & print

Detectors return warnings rather than printing them, so SmellyCodeDetector::runDetectors() can merge everything and sort once by line (then category) before printing a single ordered report.

Parallelism

runDetectors() currently runs each detector's analyzeSource() sequentially — a candidate for future parallel work.

Pairs for triples

DataClumpDetector first creates bitsets for variables in O(n^2), then stores frequent pairs in a vector. Bitset intersection for a potential pair is O(1). For triples, the detector loops through frequent pairs and all variables, costing O(F * N). It supports data clumps of three variables rather than every possible repeated subset, which would cost at least O(2^n).

API-based name generation

After a data clump is identified, DataClumpDetector delegates struct/class name generation to DataClumpNameGen, which uses curl to communicate with Google Gemini and Nlohmann/json to parse the response.

// 08  scope

Limitations of the Current Implementation

What the tool doesn't cover yet, so users don't run into a silent gap.

known limitation

Unused-function detection is call-graph only

  • DeadCodeChecker resolves direct calls and pointer-member calls with PointsToAnalyzer, including known concrete virtual overrides and callback targets. The analysis remains flow-insensitive, leaves nested blocks outside its points-to pass, and conservatively falls back to possible overrides when a pointer target is unknown. No auto-fix is offered for this check because an uncertain reachability result must not delete live code.

known limitation

Unreachable-code auto-fix is suppressed with goto/labels

  • If a function contains any goto or label, the reachability model can't account for jump targets, so the unreachable-code fix is skipped (the warning still prints) to avoid deleting a line another goto depends on.

known limitation

Chained if-return has no auto-fix

  • Collapsing consecutive if-returns into an if/else-if/else chain is a structural rewrite, not a safe text splice, so this check is warning-only.

known limitation

Single-file analysis

  • Detectors operate on one translation unit at a time; there's no cross-file/whole-project analysis (e.g. a function only called from a different file would look unused).

known limitation

Scope limited to defined smell categories

  • The tool doesn't attempt full general-purpose C++ static analysis — only the specific smells each detector targets, per the team's original scope decision.
